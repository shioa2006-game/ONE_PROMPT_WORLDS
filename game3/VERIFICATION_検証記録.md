# EMBERDEEP 制作・検証記録

※ 仕組みに触れるので軽いネタバレを含みます。結末や隠し要素の詳細は `NETABARE_攻略とネタバレ.md` 側です。

## 1. 企画比較（3案）

| 案 | 遊びの核 | 評価 |
| --- | --- | --- |
| A. 一歩＝1ターンのグリッド探索RPG（敵の予告マスを読んで動く） | 位置取りの読み合い | 検証は容易だが、手触りがパズル寄りになる。今回は「戦う手応え・冒険が進む感覚」を優先したいので見送り |
| B. 一人称 3D ダンジョン＋コマンド戦闘 | 未知の通路を進む没入感 | 探索の雰囲気は強いが、戦闘が数値の交換になりがちで、描画コストに対して「繰り返す行為の気持ちよさ」を作りにくい |
| **C. 闇の坑道を灯しながら潜るトップダウン・アクションRPG（採用）** | 斬る・避ける・火を灯す | 「叩く」一つの行動が攻撃・点火・破壊・開錠を兼ね、灯した分だけ世界が目に見えて変わる。探索・戦闘・成長を一本の線でつなげられる |

選んだ中心の喜びは **爽快感（斬る・灯す）／成長（レベル・武器・護符）／発見（闇の先・隠し部屋）**。

## 2. コアループと固有の仕掛け

- 繰り返す行動は「叩く」。同じ一撃が、カゲを斬る・火鉢を灯す（周囲のカゲを焼いて怯ませる）・木箱や宝箱を開ける・ひび壁を砕く（大槌のみ）を兼ねる。
- 火鉢をすべて灯した部屋にはカゲが戻らない。大燈を灯すと区画全体が明るくなり、地図の色が変わる。進んだ分だけ世界が安全で明るくなる。
- 武器 3 種は強さの段階ではなく道具（剣＝連撃／槍＝貫通・遠くの火鉢に届く／大槌＝盾割り・壁砕き）。Q で即持ち替え。
- 敵の攻撃は敵同士にも当たる（突進・吐き弾）。穴に弾き落とせば即死。少数のルールが場面で違う意味を持つようにした。

## 3. 実施した検証

### 機能検証

- **ヘッドレス通しプレイ**（`node tools/bot.js skilled|naive <seed>`）：DOM 非依存のロジックを 60fps 固定で回し、開始から結末まで自動プレイ。熟練方針は seed 1〜5 すべてで結末到達（結果は `tools/bot-results.txt`）。
- **実ブラウザ通しプレイ**：同じボットをブラウザに読み込み、実際のメインループ（描画・UI・音声・自動保存込み）で開始→結末→エンディング画面まで 2 回完走。コンソールエラー 0。
- **個別チェック**（`node tools/checks.js`、39 項目すべて PASS）：遠い火鉢に剣・大槌は届かず槍と閃火は届く／封印扉の開放／ひび壁は大槌のみ／盾の正面防御と殻割り／突進の壁激突／穴への落下死／灯した部屋の再出現なし／死亡→大燈で復帰（成長維持）／セーブ→ロード復元／護符 4 種の効果。
- 実ブラウザで確認：タイトル、導入、移動、マウス攻撃、キー攻撃・回避、アイテムカード、大燈メニュー（鍛冶・転移）、装備メニュー、地図、ポーズ→タイトル→「つづきから」復帰、死亡演出→復帰。

### ゲームシステム検証（単純方針 vs 工夫した方針）

| 方針 | 内容 | 結果（最終版・seed 1〜5） |
| --- | --- | --- |
| 単純 | 最寄りの敵に近づいて攻撃連打。回避・火鉢・閃火なし | 上層・中層は 0〜1 回の死亡で通過。深層の雑魚部屋で 0〜9 回死亡。最終ボスは突破不能（40 回挑戦して 0 勝） |
| 工夫 | 予兆で回避、火鉢・閃火・武器持ち替えを使う | 全 seed で結末到達、死亡 0 回、約 5 分（ボットは迷わないので人間の時間とは別物） |

→ 予兆を見て避ける・火を使うことが結果を変える。一方で序盤〜中盤は連打でもかなり進める（下の「限界」に記載）。

### 画面・操作検証

実ブラウザ 1280×720 のスクリーンショットで、3 層それぞれの見た目、暗所での敵の目・攻撃予兆（赤い帯／扇／着弾円）、火鉢点火、大燈点火、ボス戦 HUD、各メニュー、エンディングを確認。

## 4. 見つけた問題と改善

### ゲームデザイン

1. **攻撃連打で敵が何もできない** … 初期版は単純方針のボットが最終ボス手前まで被弾ほぼ 0。原因は剣の間隔が 0.16 秒と短すぎたことと、当てるたびに怯み直す「怯みハメ」。
   → 攻撃間隔を約 0.28 秒に、怯んだ敵に短い怯み耐性を付け、予備動作中は通常攻撃で止まらない（とどめの三撃目・大槌・火鉢・閃火なら止まる）ようにした。
   → 再検証：単純方針は上層ボスで 6〜14 回被弾（1 回死亡する seed あり）、工夫した方針は被弾 4 回前後。予兆を見て避ける意味が生まれた。
2. **深層で倒れると中層まで戻される** … 単純方針が深層最初の部屋で連続死し、毎回長い戻り道が発生していた。
   → 深層の入口に大燈を追加し、その部屋の敵を 1 体減らした。再検証：同部屋での再挑戦が数秒で始まる。
3. 騎士・ボスが短時間で沈みすぎたため、層ごとの敵 HP 倍率とボス HP を引き上げた（上層ボス 12 秒 → 約 28 秒／最終ボス 30 秒 → 約 60 秒、いずれも熟練ボット）。

### ビジュアル・操作感

1. **消えている大燈・火鉢が闇に溶けて見つからない** → 冷たい青の光を脈打たせ、灯す前でも目印になるようにした（スクリーンショットで視認を確認）。
2. **明暗の境目がタイル状にガタつく** → ライトマップを低解像度でぼかして合成。火の周りに暖色の光を重ね、灯した場所の「暖かさ」を強調。
3. **区画名の帯が主人公に重なる** → 画面上部へ移動。戦闘中は急がない操作ヒントを出さないようにした。
4. **入力の取りこぼし（不具合）** … 1 フレームにシミュレーションが 0 回しか進まないとき（高リフレッシュレートの画面など）に、攻撃・回避の入力が消えていた。実キー入力のテストで発覚。
   → 入力を次のシミュレーション更新まで保持するよう修正。実キーイベントで攻撃・回避・回復・地図が反応することを再確認。
5. セーブがあるときはタイトルの初期選択を「つづきから」に変更（誤って最初から始めないため）。

## 5. 限界・未確認

- **人間が面白いと感じるかは未確認**。ボットは正解ルートと全ルールを知っており、照準も完璧です。手応え・難易度・15〜30 分という想定時間はいずれも推定です。
- **音は耳で確認できていません**。音声コードは実ブラウザで例外なく動作（AudioContext running）するところまでの確認で、音量バランスや心地よさは未検証です。
- 自動操作中はブラウザ側の描画が約 30fps に絞られていたため、60fps 以上での実時間の操作感は実機未確認です。
- `index.html` を `file://` で直接開く起動は未確認です（確認は `http://localhost` 経由）。外部読み込みやモジュールは使っていないので動く想定ですが、動かない場合は README のローカルサーバー手順を使ってください。
- 序盤〜中盤は攻撃連打でもかなり進めます。短い体験で詰まらせないことを優先した結果ですが、物足りなく感じる可能性があります。
- スマートフォン（タッチ操作）は非対応です。

## 6. 遊んで確かめてほしい点

- 剣を当てたとき・火鉢を灯したとき・大燈を灯したときの気持ちよさ（音込み）。
- 暗い部屋の見え方は「雰囲気がある」範囲か、「見づらい」か。
- 上層ボスと最終ボスの難しさ。倒れたときに納得できるか。
- 隠し部屋に「あとで戻ってこよう」と思えたか。
