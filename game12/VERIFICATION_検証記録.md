## 1. 企画の選定（3案の比較）

方向性（鉄道・サイコロ・目的地・CPUとの競争）は依頼で決まっているため、その中で「主に何を繰り返し、何を楽しみに先へ進むか」が違う3案を比べた。

| 案 | 主にくり返す行動 | 採否と理由 |
| --- | --- | --- |
| **開通すごろく「ころころ、ひらけ列島」** | サイコロ → 光ったマスから とまる場所を1クリックでえらぶ → 駅で名物を買う | **採用**。目的地への一番乗り・名物を集めて決算で増やす、という馴染みのある楽しさを土台にできる。独自の工夫として「目的地に着くと、雲の向こうの地方を自分でえらんでひらける」「ひらいた地方への関所は自分のもので、通られるたびに通行料」を入れると、一番乗りが そのまま「次の景色が見える」「次の一手をえらべる」につながる。季節で地図の色と名物の旬が変わり、1年の中に変化を作れる。目押しがいらない。 |
| 行商すごろく（安く買って、高い土地で売る） | 名物を積んで、需要のある駅で売る | 不採用。ルート計画は楽しいが、とまるたびに値段の比較という重めの判断が毎回いる。サイコロで止まる場所が決まるので、計画どおりに売れない もどかしさが大きい。 |
| 切符カードで進む すごろく（サイコロの代わりに手札の数） | 手札から進む数をえらぶ | 不採用。運の要素が減り計画は立てやすいが、依頼の「サイコロで移動」から外れる。毎ターン手札の最適化を考えるのは重い。 |

採用案で決めたこと：
- **くり返す行動**：サイコロ → 行けるマスが光る → マウスをのせると「通る道」と「そこで何が起きるか」が出る → クリックで決定、列車がマスごとに「ガタン」と進む。分かれ道ごとに矢印を選ぶ方式ではなく、とまる場所を直接えらぶ（計画を立てたら、実行は1クリック）。
- **成功の大小**：晴れマス（チャリン）＜ スタンプ（ポン）＜ 名物を買う（判子）＜ 独占（ファンファーレ）＜ 目的地に一番乗り（汽笛と花火、ぴったりなら判子「ぴったり賞」）＜ 地方の開通（雲が晴れ、関所が光る）。季節のおわりの決算で、持っている名物の収益がまとめて数え上げられる。
- **次を見たい理由**：雲におおわれた地方（名前と名物だけ見える）。地方をひらくと、新しい駅と名物と目的地が現れる。季節が進むと地図の色と旬が変わる。駅スタンプ帳・名物帳はゲームをこえて残る。
- **競争**：ライバル2社（目的地まっしぐらのコン社長、名物あつめのポン社長）。一番乗り・関所・名物の取り合い・ふみきり・買収。
- **結末**：3月下旬の冬の決算のあと、総資産で順位。1位なら「にっぽん一の鉄道会社」。

## 2. つくり（概要）

- 地図：日本の海岸線を経度・緯度からおおまかに描き、51駅と 145マス（晴れ53・雨28・きっぷ26・できごと25・関所13）を路線ぞいに置く。いつも同じ配置。
- 9地方。はじめは関東・東海だけ。ほかの7地方は関所（13か所）でつながり、目的地に一番乗りした会社が、ひらける地方（いまひらいている地方と関所でつながる地方）から1つえらぶ。
- 行き先：同じマスは通らない（行き止まりのときだけ折りかえす）。目的地を通ればそこで止まる。「ぴったり」は 出目 ＝ 目的地までのいちばん近いマス数 で、そのとおりに着いたとき（賞金1.5倍）。
- 名物 161件。季節のおわりに値段の5%、旬は3倍、独占は2倍。お金がマイナスになると、独占していない安い名物から7割で手放す。
- ルールの核 `js/engine.js` は描画なしで node から動き、ボット・テスト・ブラウザが同じコードを使う。状態はふつうの JSON（乱数の状態もふくむ）なので、そのまま保存・再開できる。

## 4. システム・バランスの検証（ボット）

`node tools/sim.js <回数> <方針>`。あなた（0番）を方針で、ライバル2社はゲームと同じ CPU で動かす。ボットはサイコロの先の目を知らない。1000ゲームずつ。

| あなたの方針 | 内容 | あなたが1位 | あなたの最終資産（中央値） |
| --- | --- | --- | --- |
| smart | CPU と同じ考え方（目的地・駅・マスの損得・きっぷ・旬と独占） | 37.1% | 3億310万 |
| nobuy | smart だが 名物を買わない | 14.9% | 1億9550万 |
| nodest | smart だが 目的地に近づくことを考えない | 10.3% | 2億1760万 |
| nocard | smart だが きっぷを使わない | 7.1% | 1億6280万 |
| simple | サイコロだけ・目的地にいちばん近いマス・1駅で安いものを1つ・できごとは左 | 3.7% | 1億3140万 |

- 3社がほぼ同じ強さなら 1/3 が基準。smart は 37%（コン社長 39%、ポン社長 24%）。CPU の性格の数値を変えても勝率はほとんど動かなかった（3通りを試して ±1%以内）ので、CPU は「公平な強さ」のままにした。
- 目的地・名物・きっぷの どれを捨てても大きく負ける → 三つのしくみが どれも結果に効いている。とくに きっぷ（速く走る）の比重が大きいので、遠いときに快速・特急をすすめる ひとことを 最大3回出すようにした。
- 1ゲームあたり：目的地 約8回、ひらく地方 平均6.9（91%のゲームで全9地方）、最後に地方がひらくのは中央値 16ターン目、通行料 約17回、名物の購入 約53件・独占 約10駅、売却（借金）0.15回。
- とまれるマスの数（3社×200ゲーム）：サイコロ1こ（出目1〜6）は 中央値4・90%点8、2こ相当（7〜12）は 中央値10、3こ相当（13〜18）は 中央値22・最大61。

### ボットで見つけて直したこと

- **「ぴったり」が出すぎた**：はじめは「目的地にちょうど出目の歩数で着けば ぴったり」としていたが、輪になった路線を回り道すれば ほとんどの出目で ぴったりにできてしまい、到着の 3分の2 以上が ぴったりだった。→「出目が目的地までの いちばん近いマス数と同じとき」に変えた。
- **とまれるマスが多すぎた**（最大91か所）：同じ道を行ったり来たりできたため。→ 同じマスは通らない（行き止まりだけ折りかえす）にして、サイコロ1こなら ふつう2〜8か所になった。

## 5. 画面・演出の確認

`tools/shot.py`（手順の JSON）と通しプレイの写真で、タイトル・はじめの話・あなたの番・きっぷ選択・各停の数字えらび・行き先えらび・駅の画面・できごと・地方えらび・開通・目的地の発表・到着・独占・季節・決算・ラストスパート・結果・メニュー・あそびかた・スタンプ帳・名物帳・全体を見る・駅の吹き出し を確認した（地図の特殊な状態を作ったのは、できごと画面の描画確認1枚だけ）。

見つけて直したもの：
- タイトルで、最初のフレームの時間がマイナスになり季節の番号が −1 になって止まった → 時間の差を 0 以上に、番号を正の剰余に。
- 会社の札で お金と「目的地まで」、日付の札で 季節と「のこりターン」が重なった → 配置を変え、長い金額は字を小さくする。
- こむぎの ひとことが 手札・各停の数字えらび・駅の画面に重なった → 左上に移し、駅の画面では画面の下に細長く出す。ふったあとは その番だけの ひとことを片づける。
- 止まったサイコロが地図のまんなかに残って行き先をかくした → 止まると列車の上へ小さく移り、走りだしたら消す。CPU の移動中に「合計」と「あと○」が重なったのも これで解消。
- 結果の画面で1位の顔が文字に重なった → 表彰台を低くし、説明は見出しの帯の中へ。2位以下には「1位まで あと○円」。
- 小さいボタンで キーの印が文字に重なった → 幅のせまいボタンには印を出さない（キーは使える）。
- スタンプ帳が左半分しか使っていなかった → 2列にし、まだの駅も名前を うすく出す。

その後に足したもの（レビューで 決めたこと）：
- 3月上旬（のこり2ターン）に「ラストスパート！」と、1位との差を出す（終盤の山場を はっきりさせる）。
- 会社の札の お金は、なめらかに増減し、増えると緑・減ると赤に光る。
- 地図の駅に マウスをのせると、名物・旬・持ち主の一覧（ルート計画のため）。
- フレームレート：タイトル・プレイ中（ズーム 0.5／1.0、全地方ひらいた状態）とも 60fps（ヘッドレス Edge）。

## 7. 残っている不確実なこと・既知の問題

- **人の遊ぶ時間は 実測していない**。演出だけの時間は CPU「ふつう」で 約7.4分（1.5倍速の実測からの換算）。人が考える時間・読む時間を足して、20〜30分ほどと 見積もっている（設計上のめやす）。
- **音は 聴いていない**（合成の 実装と 呼び出しの 確認のみ）。BGM の 単調さ・効果音の 大きさは 未確認。
- 3社の強さは ほぼ互角（smart ボットで 37%）。人が 何割 勝てるかは わからない。きっぷの 比重が大きく、きっぷを 使わないと 大きく負ける（7%）。案内で 補っているが、初心者には きびしく 感じられる おそれがある。
- サイコロ3こ相当（特急）だと とまれるマスが 20〜60 か所になり、えらぶ負担が大きい場面がある（目的地は ★ で目立たせている）。
- スマートフォン：ポインターイベントで タップは 受けるが、ホバー前提の情報（道の下見・駅の一覧）は 見られない。PC 向けとして 仕上げている。
- 画面は 1280×720 を 基準に 確認した。これより 小さい窓では 文字が 小さくなる。
- 初見確認は AI の 担当 1回で、後半（10月〜3月）と 結末は 初見では 確かめていない。
