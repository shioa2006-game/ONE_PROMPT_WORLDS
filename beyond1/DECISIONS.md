# 設計判断の記録（DECISIONS）

`DESIGN.md` は利用者の初期方針の原本として変更せず、ここに開発中の判断を記録する。
「利用者が決めたこと」と「AI（Claude Code）が独自に決めたこと」を分けて書く。
数値の詳細と検証結果は `VERIFICATION.md` にある（攻略に触れる内容を含む）。

- 大名ごとの家風（特性）は残し、全国の主要大名に広げる。
- 内政の効果・資源・数値、期間、勝利・統一の条件、軍勢と賽の数は、試作とシミュレーションで決める。

## 2. AIが自律的に決めた仕様と理由

### 2.1 ゲームの土台（game15 から引き継いだもの）

- 盤面は「国ごとの城マス＋国境ごとの国境マス」のグラフ。街道1歩、峠と海路2歩。
- 1つの賽＝1つの軍勢の命令。2つ合わせる強行軍。敵の隣に入ると足が止まる。
- 城攻めは手番のはじめに城の隣にいる軍勢だけ（陣取り→次の季に攻める）。
- 余った歩数＝勢い、出目ぴったり＝奇襲、隣の味方＝加勢。合戦の式と損害の式もそのまま。
- 状態は素の JSON（node でも動く）。CPUは1手ずつの貪欲法。
- **理由**：利用者が実際に遊んで「楽しかった」と評価した手触りの中心であり、DESIGN.md も「サイコロで軍勢が動く感覚」を守るよう求めている。

### 2.2 全国マップ

- **85か国**（令制国を基本に、陸奥・出羽を16、信濃・近江・越後・伊予・土佐・肥前・肥後を2つずつに分割）。国境は160、マスは245。
- 1国1城のまま（城と領地を分けない）。**理由**：分けると game15 のルール（城攻め・守備兵・行軍）ほぼ全部に手が入り、操作も増える。
- 北海道は遊べない陸として南端だけ描く。対馬・隠岐・五島なども遊べない島。
- 海路は関門・明石・鳴門・紀伊水道・備讃瀬戸・芸予・豊予・浦賀水道・佐渡・有明海。
- 投影は緯度経度に「複数の虫めがね」（近畿・関東南奥羽・北九州・瀬戸内）をかけ、城の間隔が地方によって極端に違わないようにした（`tools/map_check.js` で最短距離と地方ごとの間隔を確認）。
- 拡大率で描く細かさを変える。全国図では勢力の色と家名、近づくと城・国境のマス・兵数・国名。右に小さな全国図と地方への移動ボタン。

### 2.3 大名

- **59家**。プレイヤーが選べる主要大名は**15家**（織田・今川・武田・上杉・北条・朝倉・三好・毛利・尼子・大友・島津・長宗我部・伊達・龍造寺・佐竹）。残り44家は「その他の大名」。
- game15 の中立の国衆は廃止し、すべての国に実在の大名を置いた（斎藤・浅井・六角・北畠・南部・葦名・河野・伊東など）。
- 主要大名は色を濃く、その他は落ち着いた色にして見分けやすくした。
- 当主名は広く知られた名を使う（例：大友宗麟）。確信の持てない小大名は「〇〇氏」とした。
- 武田は当初、北信濃を村上家に分けたが、CPU同士の対戦で武田が12局中4〜6局で滅び、史実でも1560年の武田は信濃をほぼ押さえていたため、北信濃を武田領にした（村上家は外した）。

### 2.4 サイコロと内政（中心の仕組み）

- 「1つの賽＝1つの軍勢」の game15 方式のまま、**自分の城にいる軍勢には進軍の代わりに内政を命じられる**。内政した軍勢はその季は動かない。
- 表裏（7−出目）は使わない（DESIGN.md の確定事項）。
- 内政は3種。出目の使われ方をわざと変えた。
  - **徴兵**：兵が戻る。量は国の石高で決まり、**どの目でも同じ**（秋は+1）。→ 小さい目の使い道になる。
  - **開墾**：出目ぶん進み、たまると石高+1（1段目5、2段目8。国のもとの石高+2まで）。→ 大きい目ほど早い。
  - **築城**：出目ぶん普請が進み、成ると守備兵の上限+1（最大+3）。守備兵もその場で満ちる。
- **石高**が国力：領地の石高の合計で賽の数（3＋石高÷12、最大8。京で+1）と軍勢の枠（2＋石高÷7、最大12）が決まる。
- 命令しなかった軍勢は休む（自分の城で兵+1、野外では戻らない。秋は+1）。
- **理由**：
  - game13・14 で「金が余る」「能力値の上限が埋まると内政が無意味になる」問題が出ていたため、資源は石高ひとつにし、金は作らなかった。
  - 最初の試作では「城で休むだけで兵が2戻る」ままだったため、CPUが賽の7割を使わずに休み続けた。休養を弱め、兵を戻すには徴兵（内政）が要る形にした。
  - 城を奪うと戦火で石高−1（もとの値より下がらない）・普請−1。奪った国を立て直す内政が必要になり、上限が埋まり切るのを防ぐ。

#### game13・game14 から取り入れたもの／取り入れなかったもの

| 取り入れた | 元 | 本作での形 |
|---|---|---|
| 内政した国（軍勢）はその季に出陣しない | game14 の「徴兵した国はその季に出陣できない」 | 内政した軍勢はその季は動かない |
| 出目を積み立てる開発 | game14 の積み立て式の開発 | 開墾・築城は出目ぶん進み、たまると1段上がる |
| 奪われると積み立てや国力が下がる | game13（経済・城が下がる）、game14（積み立てが消える） | 落城で石高・普請が下がり、進みは消える |
| 秋の収穫・冬の雪国 | game13・14 の秋の年貢2倍、game14 の冬の雪国 | 秋は休養と徴兵が増える。冬は峠・海路・雪国の街道が重い |
| 国の数で賽が増える | game13・14 | 石高の合計で賽と軍勢の枠が増える |

| 取り入れなかった | 理由 |
|---|---|
| 表裏（7−出目）で内政と軍事を切り替える | DESIGN.md で不採用と確定 |
| 金（資源）と、賽の買い足し・裏返し | 金が余る・上限が埋まる問題が両作で出ていた。資源を石高ひとつにして操作を減らした |
| 調略・奇襲などの命令カード | 本作では出目ぴったりの「奇襲」が game15 の仕組みとして既にある。外交は臣従だけ（利用者の決定） |
| 兵の維持費（兵糧） | game13 で「膨張か籠城」を招いた |

### 2.5 城の守り

- 本拠の守り+1と「最後の一城」の守り+2は**主要大名だけ**。
- **理由**：小大名が44家もいて、その多くが1国だけのため、全員が難攻不落になり、最初の試作では40季で城の奪取が20回しか起きなかった。
- 築城は「城の守り」ではなく「守備兵の上限」を上げる。軍勢が籠もった城には守備兵が加わらないので、籠城一辺倒にはならず、空き城を守る（＝安心して出陣できる）効果になる。

### 2.6 臣従

- 季節の終わりに判定。石高の差が5倍以上ある隣の大名の軍勢が城の隣に来ていると、2か国以下の大名が一定の確率で臣従する。遠くても差が10倍以上ならわずかに起こる。
- 京を持ち全国の石高の6割を超えた大名には、2か国以下の大名が降りやすくなる（終盤の掃討を短くする）。
- プレイヤーには申し出が届き、受ける／断るを選べる。断るとその家からは8季申し出がない。プレイヤーが臣従することはない。
- **理由**：最初の試作では条件が緩く、1局で58回の臣従が連鎖して合戦がほとんど起きなかった。「軍勢で圧をかけた結果として降る」形に絞った。

### 2.7 CPUの二層化

- 主要大名：game15 の評価関数（位置の価値・脅威・包囲・守り手のいなくなる城の損失）に、内政3種の価値を加えた。攻めっ気は game15 より少し強め（+0.15）。
- その他の大名：隣の城・隣の敵・自分の城の内政だけを見る軽い判断（勝つ見込み5割以上でしか攻めない）。6か国以上に育つと主要大名と同じ思考に切り替える。
- 遠くの大名の手番は演出せず、色の変化と記録（諸国の動き）だけで伝える。自分に関わる戦いはカメラを寄せて見せる。

### 2.8 期間・延長・勝敗

- 最初の区切りは永禄十二年の冬（40季）。区切りで「ここで決着」か「5年延長」を選ぶ。延長は何度でも。
- 決着は**石高の順位**（同じなら国の数）。1位なら「天下第一の大名」。
- 全85か国を治めると天下統一（特別な結末）。CPUが統一すると敗北。すべての城を失うと滅亡。
- メニューからいつでも「ここで決着」できる。
- 年号は永禄→元亀→天正→…と進む（1704年以降は西暦）。

### 2.9 操作量への配慮

- 軍勢一覧（左）から選ぶとカメラが寄る。状態（未・済・徴兵など）が一目で分かる。
- 委任（利用者の決定）に加え、「おまかせ」ボタンで残りの賽をまとめてCPUの思考で使える。
- 内政は軍勢を選ぶと出る小窓から1クリック（キーボード Q/W/E）。

### 2.10 難易度の表示

- 各大名をCPUと同じ思考で動かした12局×2回の、40季後の石高の平均で決めた（`VERIFICATION.md` 3.3）。
- 易：織田・北条・朝倉・島津／中：今川・武田・三好・毛利・長宗我部・龍造寺／難：上杉・尼子・大友・伊達・佐竹。
- 織田が「易」なのは、尾張の石高が高く、家風（振り直し）が強いため。史実の「小勢から」という印象とは違うが、結果に合わせた。

### 2.11 保存

- 季のはじめ・賽を振ったとき・命令のたびに自動保存（つづきから）。加えて手動の記録枠3つ。区切りの決断の画面でも保存する。
- 当初は game15 と同じく季のはじめだけ保存していたが、初見確認で「振った後に閉じると振る前に戻る」と指摘があり、命令のたびの保存に変えた（読み直しで出目や合戦をやり直せない）。

## 3. 大きな設計変更の履歴

| 時点 | 変更 | 理由 |
|---|---|---|
| 初版 | 臣従の条件を「軍勢が城の隣」中心に絞る | 臣従が連鎖して戦争が起きなかった |
| 初版 | 本拠・最後の一城の補正を主要大名だけに。築城を守備兵の上限に | 小大名の城が堅すぎて戦線が固まった |
| 初版 | 休養の回復を弱め、徴兵の量を石高で増やす | CPUが休み続け、賽の大半を使わなかった |
| 初版 | 軍勢で城が埋まっているときは城のすぐ外に出陣できる | 1国の大名が新しい軍勢を出せなくなっていた |
| 初版 | 北信濃を武田領に、甲斐の石高3・高遠城の守り2、上野の石高4 | 武田が滅びやすすぎた |
| 初版 | CPUの築城の見積もりを下げる | CPUが築城を過大評価し、「築城しない」方針のほうが伸びていた |
| 初版 | 越前の石高4、浅井に軍勢をもう1つ、加賀一向一揆を堅く | 朝倉が首位になりすぎた（16局中9局） |
| 初版 | CPUの攻めっ気+0.15、軍勢が迫ったときの臣従の確率0.18 | 強国の伸びが鈍く、脅威を感じにくかった |
| 初版 | 難易度の表示を、各大名をCPUの思考で動かした結果から決め直す | 当初の想定（史実の印象）と結果が違った。例：織田は「易」、上杉・大友は「難」 |
