# 賽駆け 天下 — 画面・操作の検証記録（0.2）

対象：2026-11-21 の UI/UX 品質改善。ルール・合戦の計算・CPUの思考・内政の数値（`js/engine.js`・`js/ai.js`・`js/data.js`）は変更していない。
変更したファイル：`css/style.css`、`index.html`、`js/main.js`、`js/render.js`（＋検証用の `tools/scenes.js`・`tools/uifix.py`・`tools/ui_check.py`）。

## 検証のしかた

- `node tools/scenes.js` が、本物のエンジンで作った保存データを出す（S01〜S15。各データに `testScene` を付け、通常のプレイで到達した状態ではないと分かるようにしている）。
- `python tools/ui_check.py` が、使い捨てのブラウザの保存領域（Playwright の新しいコンテキスト）にそのデータを入れ、タイトルの「つづきから」という通常の読み込み口から再開して、実クリック・キー入力・DOM の当たり判定（`elementFromPoint`）で確かめる。利用者のブラウザの保存データには触れない。公開版のゲームには、新しいデバッグ機能を足していない。
- 画面撮影は `tools/ui_shots/<解像度>/` に保存する（`.gitignore` でリポジトリには入れない）。
- 解像度：1920×1080、1600×900、1280×720、1180×757（Edge ヘッドレス）。
- 結果：**364項目すべて PASS**（約9分）。

## 不具合ごとの記録

### P0 賽7〜9個
- 変更前：賽が横一列のまま押し縮められ、8個で43px、9個で36px（1180×757では27px）。立方体の奥行き（27px）は変わらないので面がはみ出し、立体が崩れていた（変更前の画面を撮影して確認）。
- 原因：`.die` に `flex-shrink` が効いていた（既定値）。トレイの内側は約424pxで、7個以上は入らない。
- 修正：賽は縮めない（`flex: 0 0 54px`）。7個以上は2段（1段最大5個：4+3、4+4、5+4）にし、段の間を34pxあけて番号の札・選択の浮き上がり・振り直しボタンが重ならないようにした。（`css/style.css`、`js/main.js` の `buildTray`）
- 確認（4解像度×4シーン）：賽の数が正しい／大きさが 54px×パネルの縮尺のまま／矩形の重なり0／すべての賽の中心をクリックすると自分に届く／番号の札がボタンより上で、下の段にかからない／トレイからはみ出さない／振り直しボタンの中心がすべて自分に届き、押すと振り直せる／実クリックで選択・強行軍の2つ選択・内政の小窓（トレイの上に出る）・使用済みの表示。回転中の画面も撮影して目視（崩れなし）。

### P0 UI-01 記録などの窓の背後でキーが通る
- 変更前：記録の窓では、背後のゲームに `1`（賽の選択）や `A`（おまかせ）が届いた。`F`・`0`・`H` は遊び方・メニューの間も届いた。
- 原因：キー処理の除外が「遊び方・メニュー」だけで、記録の窓などが入っていなかった。
- 修正：臣従・区切り・記録・メニュー・遊び方・はじめにの窓が開いている間は、窓の中のキー（臣従の Enter/Esc、Esc で閉じる）以外を通さない（`modalOpen()`）。
- 確認：記録・メニュー・遊び方の各窓で `1 2 a A z Space Enter f 0 h q Shift+1` と窓の外側のクリックを送っても、賽・軍勢・選択・早送り・カメラが変わらない。窓の外側のクリックは窓が受け取る（地図に届かない）。Esc で閉じ、閉じたあとは `1` で賽を選べる。臣従（S11）・区切り（S12）の窓でも背後のキーが通らない。

### P0 UI-03 見えている進軍先をクリックできない
- 変更前：1180×757 で、`#menu-btns` の矩形が x=251〜948・y=9〜141 に広がり、画面上部の地図を覆っていた（`elementFromPoint` で確認）。変更前の CSS に戻して同じテストを走らせると、5か所中4か所でクリックが `menu-btns` に吸われて失敗した（Dots の報告と一致）。
- 原因：幅1250px以下向けの古い指定 `#menu-btns { right: 300px }`（原型の名残）と `left: 324px` が組み合わさり、見えない入れ物が横に引き伸ばされていた。
- 修正：その指定を消し、入れ物を `width: max-content`・`pointer-events: none` にして、ボタンだけがクリックを受ける（`css/style.css`）。
- 確認：4解像度で、5か所に置いた豊予海峡の陣が光っていて、その点の要素が地図（canvas）で、実クリックで軍勢が移動する。修正後、4解像度で画面全体を8pxおきに `elementFromPoint` で調べ、背景も枠もない（透明な）要素がクリックを受ける場所が0か所であることも確かめた。
- 注意：「勢力図寄り」「ミニマップ寄り」は、カメラの制限のため実際には x≒760〜790 に置いた（パネルの真横までは寄せられない）。パネルそのものの上は、見えているパネルがクリックを受ける（仕様）。

### P1 UI-02 手番終了の確認
- 変更前：ボタンは2.5秒で戻るが、案内文には「もう一度…」が残った。判定の期限（2.5秒）も別に計っていた。
- 修正：確認の状態を1つにまとめ（3秒）、期限切れでボタンと案内文の両方を戻す。ほかの操作（賽・軍勢の選択）をしたら確認を取り消す。案内文に「3秒以内に」と明記。（`js/main.js` の `endTurn`・`disarmEnd`）
- 確認：押す → 両方に「もう一度」→ 3.3秒後に両方が通常に戻る。期限内の二度押しで手番が終わる。

### P1 軍勢・地名・兵数の重なり
- 調査：S10（北九州の密集）と S05（12部隊）を各解像度・拡大率で撮影。重なりの主因は、(1) 兵数の札が、後から描く隣の軍勢の駒に隠れる、(2) 国名を軍勢の上に描くため、駒や兵数に国名がかぶる、の2つ。
- 修正：兵数の札を、すべての駒を描いたあとにもう一度描く。駒と重なる国名は薄く描く（国名は消さない）。（`js/render.js`）
- 確認：撮影で、密集した北九州でも兵数がすべて読めることを目視。全国図（縮小時）は従来どおり自軍の兵数だけを出す。
- 未対応：駒どうしが同じ位置近くに並ぶこと自体（盤面の仕様）は変えていない。

### P1 軍勢を選んだあとのカメラ移動とクリック
- 調査：カメラが動くのは、軍勢の一覧から選んだとき（画面外の軍勢へ寄る）など。描画と当たり判定は同じフレームの視点を使うので座標のずれは見つからなかったが、移動中は狙ったマスが手元で動くので、意図しない所を押しうる。Dots の報告そのものの再現（原因の特定）はできていない。
- 修正：一覧から選んだ軍勢が画面に見えているときはカメラを動かさない。カメラの移動中に地図を押すと、移動を終わらせるだけにする（命令は出さない）。（`js/main.js`・`js/render.js`）
- 確認：画面外の軍勢を一覧から選び、60ms後（移動中）に地図をクリック → 移動が終わり、賽・軍勢は変わらない（4解像度）。

### P2 軍勢が枠を超えたとき
- 修正：枠を超えているときは「/枠」を橙にし、情報欄に「軍勢・枠超え」、一覧の見出しに「（枠超え：新しい出陣なし）」と出す。説明のツールチップも付けた。ルール（既存の軍勢は残る）は変えていない。
- 確認：S10（6/3）で撮影。

### P2 賽の数の反映の時期
- 修正：今季に振った賽の数と、石高から決まる次の季の数が違うときは、情報欄を「賽・次季○」とする（ツールチップで説明）。増える時期は変えていない。
- 確認：S15 の撮影で「3 賽・次季4」と表示されることを確認（このシーンは検証用に賽の数を変えてある）。

### ついでに見つけて直したもの
- 臣従の申し出が出ている途中で閉じて再開すると、申し出が出ないままになっていた（次の季まで持ち越し）。読み込み時に申し出を出すようにした（S11 で確認）。
