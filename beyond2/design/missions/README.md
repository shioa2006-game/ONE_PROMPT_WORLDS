## 仕様書の形

どの文書も、同じ10の章でできている。

| 章 | 中身 |
| --- | --- |
| 1 基本情報 | ID・種類・依頼人・背景・推奨ランク・解放・区分・同行・想定時間 |
| 2 体験設計 | 何を楽しむか・期待する発見・立てる作戦・成功の体験・前の依頼との違い・成長と編成 |
| 3 達成・失敗 | 主目的・寄り道・戦い・失敗・帰還・受けなおし |
| 4 地図 | 高さ・地面・配置の図と、物・敵の表（**下書きデータから自動で作った図**） |
| 5 ルール | 使う決まり。既存か新規かの区別。共通の決まりは 05 を見る |
| 6 攻略の例 | 手順と座標。**「設計確認ずみ」**と書いた手は、`design/data/check_maps.js` で確かめたもの |
| 7 編成による違い | どの二人で、何が使え、何が苦手か。詰まないことの根拠 |
| 8 報酬・成長 | 銀貨・功績・品・飾り棚・店・解放・印 |
| 9 物語・台詞 | 依頼板・地図の中・ヒント・戦いのヒント・帰還・成功の演出で感じさせたいこと |
| 10 検証 | 技術の完成条件と、遊んで確かめる体験の項目（分けて書く） |

## 座標と地図

- 座標 (x, y)：x は列（左から 0）、y は行（上から 0）。`js/data.js` の `hmap[y][x]` と同じ。「北」は y が小さいほう、「東」は x が大きいほう。
- 向き：東＝+x、南＝+y、西＝−x、北＝−y（`sim.js` の `DIRS` の 0・1・2・3）。
- 高さは1段ずつの整数。のぼり1段・飛びおり2段（既存の決まり）。
- 地図の出どころは `design/data/maps_draft.js`。仕様書の4章の図は、そこから `node design/data/render_maps.js` で作っている。**地図を直すときは、下書きを直してから、確認と図の作りなおしをする。**

```bash
# beyond2/ で
node design/data/check_maps.js     # 寸法・配置・道すじの確認（現行の js/sim.js に照らす）
node design/data/render_maps.js    # 仕様書の図と表を、下書きから作りなおす
```

## 「設計確認ずみ」の意味

- 現行のルール（`js/sim.js`）で、その座標・その手順が成り立つことを、プログラムで確かめた、という意味。
- 新しい働きかけ（あおぐ・引く・つらら・雪玉）は、05 の決まりを小さな関数に写した試作で動かしている。**実装したものの検証ではない。**
- 敵をのぞいた地図で道すじを見ているものが多い。戦いを含めた達成は、実装後に確かめる（10）。
- 人が遊んで面白いかどうかは、どれも未確認。
