### 1.2 `check_maps.js` が見ていること

- 寸法（行と列の数）、谷の印が高さと地面でそろっていること、物が重なっていないこと、敵・助ける人・出発の升が立てる升（水霊は水）であること。
- 依頼ごとの道すじ：仕様書の6章で「設計確認ずみ」と書いた手を、座標どおりに実行して、行ける・届く・押せる・沈む・橋が下りる・門がひらく・救助が成立する、を確かめる。
- 新しい働きかけ（あおぐ・引く・つらら・雪玉）は、05 の決まりを小さな関数に写した**試作**で動かしている。実装そのものの検証ではない。

## 2. 実装後の技術検証

### 2.1 共通（どの段階でも）

| 項目 | やり方 |
| --- | --- |
| ルール | `rules_test.js`：05 の表の一行＝一つ以上の確認。既存の62項目が通りつづけること |
| 地図 | `check_maps.js` の項目を、実装の地図（`js/data.js`）に対して実行できるようにする（下書きと実装がずれていないこと） |
| 依頼の通し | `solve_check.js`：依頼×編成。探索は `routes.js` の手順、戦いはボット。**ボットが段取りを組めない戦い（m6・m12・m14）は、手順の通しを主にする** |
| 編成の比較 | `compare.js`：六つの編成（仲間4人）で、手番・受けた傷・使った手・倒し方 |
| 本物の操作 | `playthrough.py`：タイトル → 第一章 → 第二章の結末。読みなおしあり・なし。編成を変えて2回以上 |
| 見こみと結果の一致 | 本物の操作の通しで、押す前の見こみ（字幕・行き先・傷）と、押したあとの結果が同じ |
| 保存 | ギルドで・依頼の途中で・戦いの途中で読みなおして再開。v0.1 の保存データからの移行 |
| 戻す | 探索中は何手でも、戦いは手番の中。新しい働きかけ（あおぐ・引く・置く・床）も戻る |
| 行き詰まり | どの依頼・どの編成でも、「戻す」か「はじめからやり直す」で必ず復帰できる。行き場のない敵で戦いが終わらない、がない |
| 選べるか | 新しい物・敵・升を、画面で指して選べる（重なった絵は、向きを回す／下の升で代わりに） |
| 話し手 | その編成にいない仲間の台詞・ヒントが出ない |

### 2.2 新しい決まりごと（`rules_test.js` に足す確認の一覧）

| 決まり | 確認 |
| --- | --- |
| すき | 自分の手番にできたら、直後の敵の手番を休み、次の自分の手番の終わりまで+1。敵の手番にできたら、次の敵の手番は動く。重ねても延びない。凍らせても解けず、止まらない |
| 高所の矢 | すきなしの甲羅・毛皮に傷1（風切りの弓2）。すきありは、ふつうの計算 |
| 転がる勢い | 1升以上転がれば傷・すき。となりからは「ぶつかって止まった」 |
| あおぐ | 05 2.1 の表：物・敵・仲間 × 床・氷・水・谷・敵の上／2段上は可・3段上は不可／途中の高い物で届かない／重い物・ガルド・自分・救助される人は不可／凍った軽い敵+1／凍った重い敵はすべる／飛ぶ敵は倍・外へ出れば去る／雪玉は下りて転がる／風鳴り石 |
| 引く | 一直線・距離2〜4・2段上まで／2升でとなりに止まる／段から落ちる・沈む・すべる・転がる／重い物は不可／最初の1升が動けないと不可／レバー／傷なし |
| 連ね押し | 二つまとめて動く。三つは動かない。先頭が転がる・すべる。傷2 |
| 床を凍らせる | 乾いた升だけ変わる。水・谷・壁は変わらない。その上の物・敵がすべる。雪の上なら歩数1に |
| 置き発破 | 敵の手番の終わりに爆発。予告に出る。一度に一つ。大猪は踏むと即。戦いが終われば消える |
| 深い雪 | 戦いで歩数2。雪小鬼・雪狼・飛ぶ敵・護衛される人は1。探索では影響なし。爆風で土になる |
| つらら | 矢・爆風で落ちる。水→氷の床、床→氷のかたまり、敵→傷3（残らない／倒れたら残る）。仲間の上は不可 |
| 雪玉 | 転がる。雪2升ごとに大きく。傷2・3・4。大きさ3は止まると雪の山。水で氷の床 |
| 雪狼 | 2段のぼる・下りる。群れ+1。3段はのぼれない |
| 氷の岩人形 | 凍らない。重い。倒れると氷のかたまり（谷・水では残らない） |
| 大猪 | 05 4.6 の表の一行ずつ。ねらいは、いまの体力がいちばん低い者。凍ると休み、ねらいは残る。風鳴り石三つで毛皮がはがれる |
| 護衛 | 敵の手番のあとに2升。敵にねらわれる。倒れたら失敗。着いたら達成（戦いの途中でも）。全滅させたら一気に歩く |
| 印 | 42個それぞれ、満たす通しで付き、満たさない通しで付かない |
| お守り | 7つそれぞれの効果。一人一つ。同じ物を二人に持たせられない |
| 受けなおし | 自由編成。m3 でトビ・m8 でナギは選ぶ側に出ない。宝箱は空。報酬は4分の1・功績なし |

## 3. 人による評価

人（ゲームディレクター）と、初見の担当（設計を知らない別担当。v0.1 と同じやり方：ゲームのファイルを読まず、画面と通常の操作だけ）で行う。
**感想は、言葉のまま記録する。** 設計担当の解釈は、別の欄に書く。

### 共通で記録すること

- かかった時間（依頼ごと・ギルド）。戻す・ヒント・やり直しの回数（成績に残っている）。
- 選んだ編成と、持たせたお守り。買った順番。
- 「よかった」「困った」「これでいいのかな」と感じた所（どの依頼の、どの場面か）。

## 4. 編成の比較

| 見ること | やり方 |
| --- | --- |
| どの編成でも達成できる | `solve_check.js`（依頼×六組） |
| 編成で、使う手が変わる | `compare.js`：使った働きかけの回数、敵の倒し方（矢・落とす・沈める・転がす・当てる）、連携の回数 |
| 編成で、難しさがどれだけ違う | 手番・受けた傷・倒れた回数。**いちばん楽な組と、いちばん手のかかる組の差**を依頼ごとに出す。必須の依頼で差が3倍をこえたら、手のかかる組に手を足す |
| 人が選ぶ編成 | 評価③〜⑤の記録。六組のうち、一度も選ばれない組があれば、その理由を聞く |
| ボットの限界 | ボットは一手番先しか見ない。段取りの要る手（大岩を待つ・近道の時を選ぶ・突進をさそう）を組めない。**ボットの手番数を、人の難しさやキャラクターの優劣とみなさない**（v0.1 の記録と同じ注意） |
